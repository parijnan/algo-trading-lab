# Hestia P4: live services

**Status: slices 1 to 4 done (2026-09-28); slices 1 to 3 committed (3ff6656 is the latest); slice 5 to do.** Phase P4 of `plans/selene-production.md` §10: build the live Hestia so that it passes the same contract tests as the fake. Gate: suite green, plus gateway, idempotency and teardown tests. Several sessions of work; reported and committed per slice, only when the user asks.

## Hard constraints

1. **Nothing in P4 touches Angel One.** Prometheus trades live on Delos on the same account; any `generateSession` from anywhere else evicts its order capability (AB1007), even in DRY_RUN, and the standing rule forbids ad-hoc logins while a live strategy trades. Every live adapter is tested against a scripted `SmartConnect` double (`placeOrderFullResponse`, `orderBook`, `position`, `rmsLimit`, `getCandleData`, `ltpData`, AB1021, `DataException`/`NetworkException`, token and session errors). The first real login is a later, explicit, user-approved step (P6 territory), not part of P4.
2. **Port, do not import, from `prometheus_production/`.** Its modules pull in import-time configuration and write into the real dated log. The parity tests already show the way: compile or copy the algorithm, pin it with a test.
3. **One implementation of the policy.** The fake and the live Hestia must not be two copies of admission, priority, reconciliation and the ledger, or they drift the way the two Supertrend copies could have. So the policy is extracted once into a broker-agnostic core, and the two differ only in their ports.
4. **Paper versus live is per engine, not per process.** P8 runs Selene in DRY_RUN inside the same Hestia as live Prometheus. A paper engine gets a paper broker adapter that fills at live LTP, and its ledger is excluded from broker-book reconciliation, otherwise the first periodic read "corrects" its position to zero.

## Architecture

```
HestiaCore (hestia_core/core.py)
  request registry, admission, priority dispatch with reserved workers, depends_on, ledger, risk (margin, unit cap,
  roll window), the UNCONFIRMED -> reconciling state machine, crash / silence / KILL supervision, EngineContext
  ports: Scheduler   now / at / after        SimKernel (tests)      RealReactor (live)
         BrokerPort  place / read_order /    SimBroker (tests)      AngelBrokerPort over the gateway (live)
                     free_cash / order-update listener
         DataPort    contracts, prices, bars, ST, tracking, boundary events
                                             ReplayData (tests)     LiveData over gateway + feed (live)
         task factory  baton-passed threads (tests)                 free-running threads (live)
```

FakeHestia = core + SimKernel + SimBroker + ReplayData. LiveHestia = core + a real-time reactor (one dispatcher thread runs callbacks; blocking HTTP runs in worker threads that post their completions back to it) + the Angel One adapter + the live data service. The contract tests run against the core through the fake; the live pieces get their own tests plus a small real-time smoke subset of the same contract.

## Slice 1 record (2026-09-28)

Done. `hestia_core/core.py` holds the whole policy (`HestiaCore`, `CoreConfig`, the per-engine `CoreContext`); `ports.py` defines the three seams (`Scheduler`, `BrokerPort`, `DataPort`) and the small value types that cross them (`OrderSpec`, `PlaceResult`, `OrderRead`); `ledger.py` holds the position arithmetic shared by the core's ledger and the simulated broker's book; `replay.py` holds the simulated ports (`ReplayData`, `SimBroker`, `BrokerReply`, `ContractSpec`); `fake.py` is now a thin composition (`FakeHestia` = core + `SimKernel` + `SimBroker` + `ReplayData`) that keeps the scenario knobs the tests use. `calendar.py` became `trading_calendar.py` (and its test `test_hestia_trading_calendar.py`), because it shared a name with the standard-library module.

**Gate met:** the 83 Hestia tests that existed before the extraction pass with no edit to any test body, and the whole suite is green (288 passed, the 2 expected skips).

**What changed in behaviour, on purpose.** Only what the new BrokerPort makes natural: an UNCONFIRMED order is now settled by reading that one order (`BrokerPort.read_order`), and a row that says the order is still working (`pending`: `open`, `validation pending`, for example held by a DPL lock) is **never** reported as "no fill": the request stays UNCONFIRMED, later requests on that engine and contract keep waiting, Hestia re-reads every `reconcile_retry_s` (5 s), and raises one critical alert. Only a terminal row settles it (`complete` with the lots filled, which may be zero: rejected or cancelled). Two tests cover it (`test_order_still_working_at_the_broker_is_never_reported_as_no_fill` is mutation-checked). The simulated broker gained `BrokerReply.pending_for` to script it.

**Decisions for slice 2, noted while extracting.** The account-wide order budget (`_Bucket`, 10 a second with 4 reserved for risk-reducing classes) still lives in the core, where it gates each attempt. The gateway in slice 2 owns the per-endpoint budgets for the live calls (candle, LTP, order, book reads), so the order budget should move there and the core should only pass the priority class down; the contract test `test_order_budget_keeps_a_reserved_slice_for_exits` moves with it. The core still counts margin from `BrokerPort.free_cash()` less its own reservations; the live adapter reads `rmsLimit` for that. The paper-versus-live routing per engine and the ledger-versus-book reconciliation (excluding paper ledgers) are slice 2 as well.

## Slice 2 record (2026-09-28)

Done, against a scripted `SmartConnect` double only (`tests/smartapi_double.py`); no Angel One login was made or is possible from this code path in tests.

- **`gateway.py` (`BrokerGateway`).** One door to `obj`: a token bucket per endpoint (orders 10/s with 4 reserved for risk-reducing traffic, candles 3/s, LTP 10/s, and 1/s each for order book, positions and margin, the last three **unverified** against Angel One's published limits), one HTTP call at a time, a **priority lock** so a waiting stop takes the door before waiting normal calls, counters moved after the request even when it raises. No retry policy and no response interpretation live here.
- **`angel_broker.py` (`AngelBrokerPort`).** Ported from `place_order` / `get_fill_price_and_qty`, not imported: per-contract lot size, freeze chunking (a rejected later chunk settles what was placed as a partial and sends no more), rate-limit waits, lost-response recovery from the order book guarded by the ids this process placed and a 60 s freshness window, a bounded number of re-sends and then `unconfirmed` with a critical alert (never a blind re-send), session failures flagged, the market-close refusal, WebSocket fills with REST fallback, a `read_order` that aggregates a multi-chunk order and treats anything not terminal, missing or unreadable as **pending**, the position book converted to lots, and `free_cash` cached from `rmsLimit` and **fail-closed** (0 when missing or older than 120 s). The adapter makes one attempt and reports what happened; rejection retries stay in the core.
- **`order_feed.py` (`OrderUpdateFeed`).** The order-update WebSocket, ported; never connects on import, tests feed it messages directly.
- **Paper versus live per engine.** `BrokerPort` gained `register_engine(name, paper)`, `pool_of`, per-engine `free_cash`, and `read_positions`; `BrokerRouter` sends each engine to the live port or to `PaperBroker` (fills at the live price, a cash pool and position book per paper engine). The core takes `register(..., paper=True)`, subtracts margin reservations only within the engine's own pool, and excludes paper engines from reconciliation.
- **Ledger versus the broker's book.** `HestiaCore.bootstrap_ledger()` adopts an overnight position from the book into the live engine that owns the token's instrument (anything unattributed is a critical alert); `reconcile_ledger()` runs every 300 s and compares live engines' ledgers with the book, alert-only and never auto-corrected, skipping tokens with a request in flight and discarding a read that started before a ledger change (a snapshot older than the ledger proves nothing; mutation-checked).
- **Tests.** 33 new adapter and gateway tests, 10 account tests; every guard mutation-checked (placed-id guard, missing-order-as-complete, chunking, reserved lane, stale cash, snapshot race). The core also runs end to end on the Angel adapter against the double, including an order held open past the wait: UNCONFIRMED, never "no fill", a later close acts on the reconciled position. The whole suite is green (331 passed, the 2 expected skips).

**Deliberately left as is.** The core still runs its own order-rate budget (`_Bucket`) in front of the gateway's; the two stack harmlessly, and the core's is the engine-clash policy, so it stays. The gateway's `SessionError` is reserved for the host (slice 3). `read_order` cross-checks against `position()` only indirectly, through the periodic ledger reconciliation.

**Open for slice 3.** The adapter's blocking loops use an injected `sleep` and `clock`; the live wiring passes the real ones and a `ThreadPoolExecutor`, and needs `Scheduler.post` from the real reactor to be thread-safe.

## Slice 3 record (2026-09-28)

Done, in real time on real threads, with no broker involved beyond the simulated and scripted ones.

- **`reactor.py` (`RealReactor`).** The live `Scheduler`: one dispatcher thread runs every callback one at a time under the core lock, `after`/`at`/`post` are thread-safe (`post` is how executor workers and the order-update feed report back), and a callback that raises is logged and reported to `on_error` without ever killing the dispatcher.
- **`thread_runner.py` (`ThreadTask`, `LockedContext`).** Engines run on free-running threads; every context call takes the core lock except the blocking `next_event` / `wait` and the clock, so an engine thread and the dispatcher never touch core state at once. Events go on a queue that never blocks the sender; a thread's end is reported to the core on the dispatcher, where crash containment and auto-resume already live. A hung engine cannot be killed from outside (`abort` only wakes one blocked in `next_event` / `wait`). Heartbeat note for engine authors: the heartbeat is each `next_event` call, so an engine must loop with a timeout well under the silence threshold (180 s warn, 300 s critical).
- **`lifecycle.py` (`Lifecycle`).** Signals are installed in the main thread only (returns False elsewhere) and merely set a flag; the main thread then runs the teardown: (1) stop every engine and stop bringing crashed ones back, (2) wait for every engine thread, (3) let requests already at the broker finish and report anything left UNCONFIRMED, (4) flush Slack, (5) `terminateSession` exactly once and only if every engine thread finished, (6) stop the reactor and the pool. A hung engine leaves the session open with a critical alert unless `terminate_despite_hung` is set. A second teardown call does nothing. An engine crash never reaches any of it.
- **Core additions.** `stop_all(reason)` (also what `end_session` now does), a `_stopping` latch so no engine is launched or resumed during shutdown (a restart already scheduled when shutdown begins never happens), `in_flight_count`, `unconfirmed_requests`, `tasks_snapshot`.
- **Tests.** `tests/test_hestia_live_runtime.py` (25 tests, about 13 s): reactor ordering, thread-safe posting, cancel and survival of a raising callback; the locked context; and the contract behaviours again in real time (fill, crash containment and auto-resume, FAILED after repeated crashes, KILL with an in-flight order finishing, silence alerts, 30 duplicate ids resubmitted concurrently from two engine threads placing each order once, a stop served before an entry submitted at the same moment by another thread, 300 context calls racing the dispatcher); the teardown order, crash-never-terminates, hung engine, in-flight drain, UNCONFIRMED at shutdown, no restart while stopping; signals; and the Angel adapter on real worker threads (fill, and an order held open becoming UNCONFIRMED, settling, and a waiting close acting on it). Stable across repeated runs; every teardown and locking guard was mutation-checked (one mutation survived and led to a sharper test). Whole suite: 355 passed, the 2 expected skips.

**Left for slices 4 and 5.** The live data service still to build (the tests use a stub data source); the host wiring (`hestia.py`) that builds the gateway, adapter, feed, reactor, executor and lifecycle around a real login and passes `terminate = obj.terminateSession(...)` and the Slack flush; the alert sink (the core still appends to `core.alerts`, slice 5 routes it to Slack and logs); wall-clock convention (the reactor uses naive local `datetime.now`, like the rest of the repo, so the host's timezone must be IST).

## Slice 4 record (2026-09-28)

Done, against a candle double that serves 1-minute frames as of the simulated clock and can fail on demand; no broker involved.

- **`mcx_market.py`.** `MarketCalendar` (holidays file, full closures, evening-only days, session open 09:00 or 17:00, the US-DST-dependent close 23:30 or 23:55, holiday-aware trading days left) and `ContractCatalog` (instrument master: lot size, freeze quantity converted from units to lots, tick converted from paise, each contract's own pipeline file). Pinned against production's `_resolve_closing_time`, `mcx_fully_closed_today` and `mcx_evening_only_today` on every day of five years and every day in the real holiday file.
- **`history.py`.** Past days from the pipeline file (tail read), a per-token append-only intraday cache, the 15-minute resampler (09:00 anchor, a window counts only once done, the short last bucket on a 23:55 day kept) and the gap check. The resampler and gap check are pinned against production's, compiled from its source, on multi-day frames with missing minutes and both closing times. Fixed on the way: a pipeline file shorter than the tail repeats its header as a data row and turns every column to text (never seen in production because its files are long; found by a short test file).
- **`candle_fetch.py`, `feed_port.py`, `gateway.market_data`.** The resilient window fetch (a burst of attempts, `None` on failure so the window is queued for recovery, an empty frame on a successful fetch with nothing new), the day-chunk history fetch with rate-limit back-off, the `FeedPort` seam and an adapter over `websocket_feed.SharedFeed`, and the quote call that carries the circuit limits.
- **`live_data.py` (`LiveData`, the live `DataPort`).** Seeding (backfill, past, cache, gap fetch, resample, refuse on a hole), one poll per minute per active token staggered under the gateway budget with a recovery queue for windows a failed burst left behind, 15-minute bar building with a cutoff and quality flags (COMPLETE, RECOVERED, PARTIAL, GAP), a provisional bar from the tick feed when the window is incomplete at its boundary and `reconciles_provisional` on the real one, Supertrend per (token, engine spec) from the one implementation, prices with their age (feed, then REST, then the last bar), feed-stale and DPL-freeze events, contract tracking, and the guarantee that every tracked contract's bar for a boundary is readable before the trading contract's `BarComplete` is delivered (with a release and a warning if a tracked stream stops finalizing). The core calls an optional `trading_contract_set` hook so a contract an engine starts trading is served at once.
- **Gate met.** For the same minutes, `LiveData` and `ReplayData` deliver the same 58 bars with the same Supertrend, previous Supertrend, flips, quality and minute counts (floats compared to 1e-9: a pipeline CSV round trip costs one ulp of a synthetic price, real two-decimal broker prices survive it exactly).
- **Tests.** 38 new test functions (market 6, history 8, fetch and feed adapter 7, data service 17), the data-service ones covering: an AB1021 stretch giving a provisional bar and then the recovered real bar, the same without tick data, a window built PARTIAL at the cutoff, a late minute completing a bar as RECOVERED, a window with no data as a GAP, a restart reusing the cache and fetching only the gap, a hole refusing the seed, tracked-first with a 20 s stagger, a stuck tracked stream released with a warning, an evening-only session where the window before 17:00 is not a gap, a forming minute never stored, and backfill going to a private file with the pipeline file byte-identical. The guards were mutation-checked (forming minute, tracked-first, cutoff, pre-open skip, backfill target, provisional). Whole suite: 405 passed, the 2 expected skips.

**Deliberate differences from Prometheus, all defensive.** The minute still forming when a poll runs is dropped before it can reach the keep-first cache (a partial candle stored there would seed a wrong bar after a restart). The backfill check is by day (history reaching back to the day it is needed from), not by timestamp. Backfill results go to a private file, never the pipeline's. The intraday cache is one file per token. The dual-tracking poll offset (27 s) is replaced by a general per-token stagger.

**Not ported, on purpose.** The opening-bar correction and the 1-hour filter (both off in Prometheus), the debug dump of the 15-minute series, the DPL band announcements to Slack, and the rollover prefetch and top-up polls (a tracked contract is simply polled like any other; what the roll decision does with its bars is the engine's roll library). `historical_basis_price` and `compute_st_for_contract` (the veto) belong to that library, which reads `st_series` and `price_near` from this service.

**Left for slice 5.** The host that wires the real gateway, feed, executor, reactor, lifecycle and this service around a login; the alert sink to Slack and logs; flags; state files; the session lock; the per-engine `DataSpec.seed_days` (the service uses one `LiveDataConfig.seed_days`); and configuration in `hestia_config.py`.
